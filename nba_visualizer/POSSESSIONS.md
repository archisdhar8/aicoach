# Historical NBA possessions

The historical-possession feature imports public event data without presenting
it as player tracking. Its boundary is `PossessionDataProvider`; application
services and UI contracts do not import `pbpstats` or `nba_api` classes.

## Sources and fallback

The primary adapter uses `pbpstats.client.Client` with the `Possessions`
resource, `source="web"`, and `data_provider="stats_nba"`. The fallback adapter
uses `nba_api.stats.endpoints.playbyplayv3.PlayByPlayV3`, dataset
`PlayByPlay`. The NBA.com adapter groups ordered public events into normalized
possessions when provider identifiers or terminal events make that possible.
It does not claim the grouping is tracking-derived.

The provider chain is bounded: pbpstats gets one attempt, then the existing
bounded/retrying NBA.com provider is tried. A successful normalized response is
written to SQLite. If refresh fails, the latest cached snapshot is returned
with `cacheStatus="cache_fallback"`; if no cache exists, the API returns a
structured 503. Unit tests use the saved fixture in
`backend/tests/fixtures/pbpstats_possessions.json` and make no live requests.

## Normalized data and provenance

`RealPossession` contains game/period clocks, offense and defense team IDs,
available on-court lineups, ordered events, result, and source identifiers.
Events preserve available shooter, assist/passer, turnover, foul, rebound,
shot coordinates/type/result, and clock fields. Missing values remain null or
empty; they are never filled with guesses.

Every normalized field has a `FieldProvenance` entry with one of:

- `observed`: directly supplied by public source data.
- `derived`: deterministically calculated or inferred from a source field.
- `manual`: entered by a user.
- `simulated`: generated by the simulation engine.
- `unavailable`: not supplied by the source.

Historical snapshots are append-only by `(possession_id, retrieved_at)`.
Manual `Play` reconstructions live in `possession_reconstructions`, reference
the source possession, and cannot overwrite the historical snapshot. Routes
created after loading a real possession carry
`provenance="manual_reconstruction"`.

## Public-data limitations

Standard NBA public APIs and pbpstats do **not** provide full frame-by-frame
x/y coordinates for all ten players. This feature does not generate cuts,
screens, defensive movement, ball trajectories, or starting court locations
from historical fact. Shot coordinates may be present for some shot events,
with provider-dependent coverage and coordinate conventions.

Lineups may be derived from substitutions and may be incomplete when source
events are missing or malformed. The editor only enables reconstruction when a
complete 5-on-5 lineup is available. It loads those players into clearly
labeled placeholder court positions and creates no routes or actions. Users
must place players and draw routes manually; those edits are labeled manual
reconstruction, not observed history.

## API and UI flow

- `GET /api/v1/nba/games` searches games by team, season, or date.
- `GET /api/v1/nba/games/{game_id}/possessions` loads normalized possessions.
- `GET /api/v1/real-possessions/{id}` returns one source snapshot.
- `GET|POST /api/v1/real-possessions/{id}/reconstructions` reads or stores
  separate user reconstructions.

The UI follows game picker → filtered possession list → provenance-aware event
details → optional manual reconstruction. Filters cover player, quarter,
made/missed, turnover, and available shot type.
